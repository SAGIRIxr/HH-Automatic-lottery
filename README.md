## 功能

- **奖项明细** —— 按类别聚合中奖次数、占比、累计数值，可展开到具体档位
- **官方爆率对比** —— 读抽奖页奖池里的爆率字段，把实测占比和官方公布值并排显示。**站点 2026-08-19 把 `probability` 和 `probability_real` 双双撤掉了，页面上只剩排序用的 `priority`**，所以这块现在会自动停用并在日志里说明，只显示实测数据。字段回来了脚本会自己恢复，两种格式都认
- **大奖全屏庆祝** —— 中到 VIP 或 780,000 憨豆时整屏压暗 + 金色光芒 + 三束礼花。爆率读得到时按爆率判（低于 0.2% 才算），读不到就退回「VIP 或单笔十万以上憨豆」的硬规则，不会跟着一起失效
- **🏆 命中奖项就停** —— 两个独立复选项：**VIP（含折算）**、**780,000 憨豆**，可单选、全选或全不选。VIP 即使按站点规则折算成 1,000,000 憨豆，仍只算 VIP；憨豆项只认 780,000 这一档，不会被普通 1,000,000 憨豆误触发。两项默认都关，VIP 会等折算核完再停
- **一抽到底** —— 忽略最大次数，一直抽到余额跌破你设的保留线为止（默认保留 0），不限次数。挂机期间站点调爆率或调价都会被跟进，只记日志不打断
- **大奖名册** —— 780,000 憨豆和 VIP 这两档几千抽才碰一次，冒险日志只留 50 条根本回看不到。中了就连时间一起记进名册，跟着历史统计走，关页面、换会话都还在
- **全屏庆祝留够截图时间** —— 停 15 秒，带倒计时和关闭按钮，点任意处或按 Esc 也能关；期间抽奖在后台照跑
- **VIP 折算** —— 抽奖页写着「中 VIP 时，如果用户已经是 VIP 或以上等级，奖励憨豆 1000000」，但接口返回的文案还是 VIP。中到 VIP 会当场回服务端核一次余额，真多出一大笔就把档位标成「已转换为憨豆」——**这一注仍然算一次 VIP 中奖**，只是收益记成憨豆，爆率统计和盈亏两头都不错
- **站内信清理** —— 站点每抽一次就发一封「幸运大转盘 中奖通知」，挂机一晚收件箱就被埋了。**🗑 立即清空**扫完整个收件箱，弹确认框二选一：**只删抽奖通知**（其余原样保留，删完还会补扫一次，把删除期间新到的也收掉）或**全部删除**（整个收件箱清空）。**📪 自动删抽奖站内信**在挂机时每 25 抽顺手清一次，只删抽奖通知，不碰别的。收件箱每页显示条数太小（站点设置里的 `pmnum`，有人设成 10）会导致要翻上百页，脚本发现页数多时会问一句要不要改成每页 100 —— 改的时候整张网站设定表单按当前值原样回填，只动这一项
- **实时憨豆余额** —— 每抽本地结算（扣消耗、加中奖），每 25 抽回服务端拉一次权威值校准漂移，也可手动点 🔄
- **备份 / 导入** —— 导出可回灌的 JSON 备份，换设备时把统计带走；导入时三选一：**合并**（两边记录相加，换设备用这个）、覆盖、取消
- **重复导入会被拦一道** —— 统计存的是累加值，同一份记录合两次就被算两遍。备份带记录线编号，认得出「这个文件导过了」「两边同源」；老备份没编号的，靠大奖时刻对表。查出重叠会弹警告并把推荐项换成覆盖或取消，但不堵死合并
- **汇总统计** —— 抽奖次数、消耗、各类奖品累计，支持「本次数据 / 历史总计」切换，存 `localStorage`
- **CSV 导出** —— 导出当前视图的分奖项明细，带 BOM，Excel 打开不乱码
- 间隔 / 次数 / 视图 / 面板位置 / 动画开关 / 一抽到底 / 保留憨豆 / 自动删站内信 / 两个中奖停止项全部持久化；面板可拖动，支持触屏；多标签页统计不互相覆盖；尊重系统的「减弱动态效果」

> **关于「魔力」和「憨豆」**：站点奖池里 `type 1001` 的 `typeText` 写作「魔力」，但它用的图标是 `bean_icon`、消耗侧也叫憨豆 —— 同一种货币，NexusPHP 的默认叫法没改干净。所以脚本把两者归到同一类，盈亏才算得对。本仓库早先的版本一度把它们拆开统计，导致盈亏少算一大半，现已改回；那样存下来的旧数据在读取时会自动合并。

## 相比原版改了什么

**统计**

- 详细奖品统计容器写死了 `display:none` 且没有任何代码改回来，那个展开按钮从来没出现过 —— 数据一直写进不可见的 DOM
- 统计粒度从「完整奖品文案」改为「类别 → 档位」两层聚合，不再几十条碎片
- 「本次中奖」恒等于抽奖次数、没有信息量，改成奖项种类数

**抽奖行为**

- `setInterval` 周期调用 `async` 抽奖函数，请求慢过间隔就会并发发起，重复扣豆并触发重复点击风控 —— 改成 await 完成后再排下一次的串行循环
- 串行化同时消掉了 `startLottery()` 里 timer 引用被覆盖导致的定时器泄漏，以及退避到 30 秒后间隔再也降不回来的问题
- 单次消耗用 `match(/(\d+)/)` 解析，遇到 `2,000` 只取到 `2`，可抽次数和盈亏率全错
- 接口非限流类错误只累加计数器不做任何事，一直 500 就会无限刷请求 —— 现在连续 5 次失败 / 12 次限流自动停止
- 限流和接口错误改为分开计数，几次限流叠上一两次网络抖动不再被误判成接口异常停机
- 抽奖间隔严格按设定值执行，可精确到小数点后两位；停止按钮可立刻中断等待
- 自适应延迟：站点的冷却窗口就等于上一抽返回的 `data.duration`。2026-08-21 在 `lucky.php` 上实测 —— 上一抽 7666ms 要等到 7211ms 才放行，3976ms 的 4322ms 就放行；duration 本身随机（采样 3976~7666ms）。所以任何固定间隔都躲不掉「不要重复点击」：填 5.1 秒时，凡是 duration 超过 5.1 秒的那些抽下一抽必被拒。现在按上一抽的 `duration` 排队（100 抽实测 0 被拒）。计时起点是「发出请求」那一刻 —— 服务端在请求路上就开始计时，所以缓冲默认 0，面板可调（−500~5000ms，负值即贴边）。自适应开着时手填的间隔完全不参与，输入框置灰。被「不要重复点击」挡回不扣憨豆也不重置服务端计时（实测连吃 16 个拒绝后照样按原时刻放行），300ms 后自动补一枪

**其他**

- 设置与面板位置持久化，运行中改间隔立刻生效
- 拖动兼容触屏（原本只绑了 mouse 事件）
- 多标签页统计改为读-改-写
- 页面切到后台时跳过中奖动画，省掉每次 20+ 个粒子节点
- 请求头对齐站点自身的 `jQuery.post`
- 导出 CSV 的排序补上并列时的次序兜底，和面板渲染一致
- 兜底文案表的 key 统一 trim（接口返回常带尾随空格，同一个奖以前会留下两条）
- 站点抽奖后从不刷新页面上的憨豆余额元素，导致自动抽奖期间面板余额和「最多可抽」一路冻结 —— 改为每抽本地扣减，DOM 值自己变化时再重新采信

**数据迁移**：存储 key 从 `hhanclub_lottery_stats_v3` 升到 `v4`，首次运行自动迁移，历史数据一条不丢，旧 key 保留不删。早先版本误拆出来的独立「魔力」分类，读取时自动合回憨豆。

## 开发

```bash
npm install

npm test        # 行为测试，约 6 分钟（用的是真实计时器）
```

在 GreasyFork 脚本管理页选择「从代码仓库同步」，地址填：

```
https://raw.githubusercontent.com/SAGIRIxr/HH-Automatic-lottery/main/hhclub-auto-lottery.user.js
```

之后改动提交到 `main` 并升高 `@version` 即可自动拉取。
